# Command Centre exports and audit log

## Behavior

CSV exports for Overview, Games, Funnels, Multiplayer, and Reliability are generated by `decked_export_command_centre_csv`. The browser supplies the active filter set and a unique request ID. Games additionally supplies the identifiers in the visible sorted and filtered table, so the downloaded rows match the screen.

Every data row contains `generated_at`, `data_freshness`, `environment`, `date_from`, and `date_to`. Column names are stable and report-specific. Cells are quoted, quotes are escaped, and spreadsheet-formula prefixes are neutralized. Export authorization, report validation, and audit insertion occur in the trusted database function. The audit entry stores only report/filter metadata and row count—never CSV contents, prompts, room codes, tokens, or raw analytics identifiers.

Grouped diagnostic and multiplayer labels receive an additional server-side stable-label allowlist before export. Values containing whitespace, message-like punctuation, secrets, or more than 160 characters are replaced with `redacted`, even if historical data bypassed normal ingestion validation.

The Settings route contains the administrative audit viewer. The database requires an active `admin` role and returns at most 500 records. Actor IDs are replaced with a stable one-way label, target references and arbitrary JSON properties are omitted, and only an allowlisted metadata summary is returned. Viewer accounts receive no audit rows.

Role changes use `decked_set_command_centre_staff_role`; it validates role/status, records old and new values, deduplicates by request ID, and prevents removal of the final active administrator. No settings mutation or room-level investigation workflow exists in the repository yet, so those actions are listed as audit-filter categories but are not fabricated. Future trusted workflows must insert `settings_changed` or `room_investigation_started` in the same transaction as the action.

The audit viewer builds summaries from an action-specific allowlist: report/range/count for exports, old/new role and status for staff changes, setting key for future settings changes, and reason code for any future privacy-safe room investigation. Target references and arbitrary properties are never returned.

## Security and privacy checks

- Raw analytics tables and audit tables remain unavailable to browser roles.
- Every export and audit RPC rechecks staff authorization server-side.
- Export entries contain metadata only; the audit viewer cannot retrieve raw actor UUIDs, target references, or property JSON.
- CSV formula injection is neutralized before download.
- Environment and date bounds are validated by the shared query validator.
- Repeated request IDs do not duplicate export or role-change audit entries.

## Verification and reconciliation

Run:

```sh
npm run lint
npm run typecheck
npm test
npm run build
supabase db reset
```

`supabase/tests/command_centre_aggregates.sql` covers unauthorized access, formula neutralization, filtered-export consistency, request deduplication, metadata-only audit entries, role-change auditing, final-admin protection, and audit redaction. The frontend test creates a 50,000-row CSV blob to exercise the large-download path.

After non-production deployment, export a filtered Games table and compare `row_count` with the visible table. Confirm one `report_exported` row with the same report, environment, date range, and count. Run the existing aggregate reconciliation function for the dates before comparing report totals.

## Deployment and rollback

Apply `20261009243000_command_centre_exports.sql`, `20261009263000_command_centre_games_export_consistency.sql`, and then `20261009270000_command_centre_export_audit_hardening.sql`. Deploy the client only after the migrations succeed.

Rollback is additive and preserves audit evidence:

1. Deploy the prior client to remove export controls and the audit viewer.
2. Revoke execute on the three new public RPCs from `authenticated`.
3. To roll back only the hardening migration, restore the prior definitions of `decked_export_command_centre_csv` and `decked_command_centre_audit_log`, then drop `decked_export_safe_label`.
4. Drop the export/audit RPCs and `decked_csv_cell` only after confirming no deployed client calls them.
5. Do not delete `command_centre_audit_log`; retaining accountability records is intentional.

The migration does not alter gameplay tables, gameplay policies, or existing RPC response shapes.
