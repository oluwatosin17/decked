## Remaining release blockers and their dependencies

1. **Backend deployment and migration history.** The current PR adds database functions and report fixes that the sole live Supabase project has not been shown to have. The earlier Spelling Bee RPC check was a concrete 404. Reconcile local and remote migration history, review an exact deployment plan, then apply the approved migrations and confirm required RPC signatures. This needs explicit approval because it changes the only live project. The local full chain cannot certify remote history or migration order on that project.
2. **Current-PR Realtime and real-network acceptance.** The local Spelling Bee run used polling/refresh, with no Realtime server; prior Read My Lips runs used browser contexts on one host. Acceptance needs four clients with the deployed backend and at least two physical devices/networks, covering push latency, privacy, timeout, disconnect/reconnect, subscription cleanup and Read My Lips audio/video. It creates gameplay and analytics records on the only live project, so it needs an approved production-safe test window or equivalent authorized environment.
3. **Staff reporting and operations on the deployed revision.** Authorized viewer/editor/admin browser acceptance must confirm actual report filters/exports/counts, feedback transitions, content revision conflicts/rollback, audit entries and role denials against known records. Only synthetic local roles were available for the current PR. The prior live admin-only section visits and old metrics are insufficient for sign-off.
4. **Human content and audio approval for any expanded Spelling Bee release.** Review the 934 drafts and 35 held entries, produce/verify pronunciation for approved words, and listen-check the shipped 36-word audio set on target devices. Until then, the 934 drafts must stay unpublished; bundled fallback remains available.
5. **Full-product hands-on acceptance.** Route smoke and automated audits do not prove the complete rules of every canonical game or accessibility on real devices. A release owner must accept that scope or complete representative gameplay, responsive and assistive-technology checks before claiming a full-product release.

These are the concrete gates. The broad lint-warning backlog, large PR size and build chunk warning are review risks, not independently demonstrated release failures here. The [review map](spelling-bee-candidate/PR_REVIEW_MAP.md) gives reviewers separate ownership for Spelling Bee, Read My Lips, Command Centre, shared wiring and editorial content.
