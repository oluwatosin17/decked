# Spelling Bee local end-to-end QA — 8 November 2026

## Decision

**Keep draft PR #15 in Draft.** The rotating speller and timed submission rules are the agreed first-release scope; buzzer and steal actions are deferred. This run proves a substantial local path through the game and Command Centre, but it does not prove production deployment, Supabase Realtime delivery, separate networks or devices, or editorial/audio readiness.

No production Supabase records were changed. All accounts and content changes below lived in disposable local Postgres. The 934 candidate words remain unpublished drafts in the source package and in this local test.

## Environment and reproduction

- Branch: `feature/spelling-bee-candidate-integration` at the time of this report.
- App: Vite on `127.0.0.1:5174`, using `VITE_SUPABASE_URL=http://127.0.0.1:54321` and `VITE_SUPABASE_PUBLISHABLE_KEY=local-qa`.
- API: local `scripts/qa-spelling-local-api.mjs` proxy to PostgREST v16.5 on `127.0.0.1:3002`.
- Database: disposable `decked-spelling-e2e-db` container from `public.ecr.aws/supabase/postgres:17.6.1.127`, with all applicable repository migrations through `20261108120000` applied in filename order.
- Browsers: Google Chrome through Playwright; four separate contexts and local sessions, including a 390 px mobile viewport. Set `PLAYWRIGHT_MODULE_PATH` and `CHROME_PATH` if the defaults in the scripts do not match the machine.
- Test users: four synthetic anonymous players plus synthetic viewer, editor and admin rows in local `auth.users` and `command_centre_staff`. JWTs use a test-only local secret.

The bare Postgres image required local Auth/Storage compatibility scaffolding (`auth.users.is_anonymous`, minimal Storage tables/functions, and `auth.uid()` reading PostgREST claims). Migration `20261010134000_fix_play_patterns_hour_ambiguity.sql` could not rewrite a function body on this fresh image and was skipped; later migrations applied. This means the exercise is not proof of a clean production migration chain. To repeat the browser runs after setting up this isolated stack, run `node scripts/qa-spelling-four-browser.mjs` and `node scripts/qa-command-centre-browser.mjs` from `app/`. The scripts default to localhost; keep `DECKED_QA_URL` pointed at an isolated local app because the flows create rooms and content records.

Run the rollback SQL regression with `psql -X -v ON_ERROR_STOP=1 -f supabase/tests/spelling_bee_command_centre_games.sql` against the disposable database. It inserts a temporary completed session, verifies the 30-row Games inventory, new game activity, CSV output and export audit event, then rolls back.

## Four-client game evidence

| Step | Observation |
| --- | --- |
| Entry and room | Four separate Chrome contexts loaded Play Together. One created a room; three joined by code. Host saw all four players. |
| Setup | Host assigned two teams of two, Easy and Medium levels, 20-second turns, and two rounds per team. |
| Fairness | Server secret deck contained four turns: both teams saw the same level within a round and levels rotated Easy/Medium between rounds. |
| Privacy | The active speller's private RPC returned audio ID and definition but no answer word. Each other client's RPC returned null word, audio ID and definition; opponent UI had no answer field. Public audio asset IDs are not cryptographic secrecy. |
| Turn 1 | Alpha submitted the correct server word and scored one. |
| Turn 2 | Beta submitted an incorrect spelling and scored zero. |
| Reconnect and timeout | Alpha's second speller closed and reopened its page with the same session, resumed turn 3, then timed out; score stayed zero for that turn. |
| Final result | Beta's final incorrect turn ended the game. UI displayed `WINNER: ALPHA`; database room state was `finished`, `sp_scores=[1,0]`, `sp_phase=done`. |

The successful browser run exited 0. [Final result screenshot](../assets/spelling-bee-four-browser-final-2026-11-08.png). Refresh and focus polling were used between clients because the local stack did not include Supabase Realtime. Therefore this run does **not** establish subscription behavior, push latency, separate-device operation, or cross-network resilience. It does establish server state recovery after a browser page reconnection.

## Command Centre evidence

All 11 sections—Overview, Acquisition, Games, Funnels, Multiplayer, Geography, Play Patterns, Reliability, Content, Feedback, and Settings—were navigable in each of three isolated staff browser contexts (viewer, editor, admin), with no failed RPC responses in the recorded pass. Viewer had no upload or publish controls; editor and admin had them. The viewer was exercised at 390 px width. This is a navigation and access smoke pass, not deep validation of every filter, chart, feedback action, or responsive breakpoint.

The editor uploaded the prepared 934-row JSON through the UI. Preview identified 934 words requiring editorial review; import succeeded as drafts. A repeat import left the same 934 draft memberships. Publication was blocked while review and approved audio were missing. Editing `river` through the structured editor advanced its local version by one on each run (v13 to v14 in the final pass); the success status remained visible after refresh. Local content showed 934 draft memberships and zero published.

The admin Games table displayed **6** Spelling Bee multiplayer starts, equal to the **6** local `analytics_game_sessions` rows at the time of the final pass. Five are iterative local QA rooms, one is the successful final run. The displayed completion percentage also matched the completed row count. The Games CSV download included `spelling-bee`; the Settings audit log showed the export. [Command Centre screenshot](../assets/spelling-bee-command-centre-2026-11-08.png).

## Defects fixed and regression coverage

1. The Games database RPC still enumerated 28 games, omitting Read My Lips and Spelling Bee. The client filled in zero rows, hiding real sessions. Migration `20261108110000_command_centre_new_game_inventory.sql` now emits all 30 canonical games. The rollback SQL test asserts the inventory and Spelling Bee counts; the browser test reconciles displayed starts and completion rate against database rows.
2. Games CSV export rejected visible IDs for these games because its allowlist was stale. Migration `20261108120000_command_centre_games_export_inventory.sql` validates against the Games report inventory. The rollback SQL test and browser download both pass; the audit log is asserted.
3. Content operations set a success status before `load()`, which cleared it. `ContentPage.tsx` now sets archive, publish, import and save statuses after refresh. The browser test waits for successful import and draft-save notices.

## Open release gates

- Verify intended Supabase migrations and RPCs in the actual release environment, including the old Play Patterns migration compatibility. No production migration was attempted here.
- Run four independent devices and networks with real Supabase Realtime, including subscription cleanup, disconnect/reconnect, and live latency. The local run used four browser contexts on one machine and network.
- Complete deeper Command Centre browser coverage: report filters and analytics detail in every section, feedback operations, revision conflict, rollback, and all permission boundaries using authorized real staff access. The local role smoke is narrower.
- Editorially review all 934 drafts and 35 held words; produce and listen-check pronunciation audio, including Nigerian English and regional spellings. Only 36 bundled pronunciation files are currently available.
- Complete the broader Decked product regression and independent review of Read My Lips and shared changes in this large PR.

No full-product release is recommended from this evidence. Keep PR #15 in Draft.
